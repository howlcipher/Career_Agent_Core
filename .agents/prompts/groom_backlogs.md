# Groom the Backlogs

Maintenance pass over `bugs.md`, `improvements.md`, `improvements_paywall.md`, and `documentation/task_journals/`. Do not implement any backlog item during this pass. `improvements_paywall.md` mirrors `improvements.md`'s format and gets the same re-evaluation/re-scoring treatment (steps 2-4 below) — it just holds items that need a paid signup/subscription/API key, so `/work_next_item` skips it by default. If a groom pass finds an item in `improvements.md` that turns out to need a paid service (or vice versa), move its row and Details section to the correct file in the same commit.

**Subagents and delegation:** when re-verification fans out across many items or files, you may parallelize it with subagents or delegate it, subject to the delegation policy in `work_next_item.md`: read-only verification subagents (e.g. Claude Code's Explore agent) are allowed but bill the same plan as the session, so for limit-saving prefer headless Antigravity (`agy -p`) or local Ollama for self-contained verification briefs. All edits to the backlog documents, rankings, and journals stay in this session, and every claim a subagent or delegate reports must be spot-checked (grep the actual code) before it changes a row.

**Verifying claims, not counts.** Steps 2-4 below say to re-verify each row against current code. The failure mode that survived a dozen passes of exactly that instruction (improvement #455) was re-running a row's *count* and never testing the *claim the count supported* — a fabricated model ID sat in seven rows for four days while every pass reported the backlog re-verified. When a row pairs a number with a categorical assertion ("…which no longer exists", "…all of which are broken"), the number re-running clean is not evidence for the assertion. Check the category against an authoritative source. Where that check can be mechanical it should already be a test rather than a step in this prompt — `internal/backlog` and `pkg/config` hold the ones that exist, and `go test ./...` runs them.

**Model fallback:** each row names a capability **Tier** (`mechanical` / `standard` / `deep-reasoning`, improvement #456), not a specific model — a starting point for how capable a delegate needs to be, not a requirement. `go test ./...` enforces that every Pending row names one of the three tiers (`internal/backlog`); it does not check what model you actually use, since a tier does not expire the way a model ID did (improvement #455). `documentation/model_allowlist.md`'s "Tier → model starting point" table translates a tier into a concrete model per provider — check live availability before trusting it (`agy models`, `curl localhost:11434/api/tags`). Probe availability live before delegating, then walk down this ladder until something works: (1) the concrete model the tier table names for whatever host CLI you're running in; (2) another tier on the same subscription, stepping *down* one level rather than giving up (Antigravity: `agy models`, quota is shared across Gemini tiers; Claude Code: Sonnet → Haiku); (3) local Ollama (`curl localhost:11434/api/tags`); (4) the session's own model doing the work inline. Only report the pass blocked if every rung fails — a groom is mostly reading and editing markdown, so any available model is acceptable, even one below the row's ideal tier.

Update, merge, or close stale items with a dated note; keep table rows and detail sections in sync.
3. Re-score and re-rank every Pending row using the diminishing-returns model defined in `improvements.md`: **Score = (Value 1–8 × Decay) ÷ Effort 1–8**, where Decay halves for each already-shipped item in the same theme and stays 1.0 for new-capability items. Recompute all scores here rather than trusting last groom's numbers.
4. Apply the **ROI floor (0.5)**: flag every Pending row scoring below it with `⚠️ below floor` and a dated scoring note. Below-floor items stay open — never close one unilaterally — but must not be worked without explicit user confirmation; surface each one to the user with a recommendation (confirm, re-scope, or close). Clear the flag when a re-score lifts an item back above the floor.
5. Journals: delete any journal whose item is no longer outstanding, and consolidate any journal too large to skim, preserving its Next Step line.
6. Commit the grooming as `docs(backlog): <summary>` and push.
